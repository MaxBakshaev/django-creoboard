## 2. Организация агентов

Работа с Claude Code построена как конвейер на одного человека и нескольких специализированных субагентов. У каждого субагента свой контекст и свои права (файлы `.claude/agents/`).

| Агент | Роль | Права |
|---|---|---|
| `backend-dev` | Реализация Django/DRF-кода по шагу плана | чтение, запись, bash |
| `frontend-dev` | Реализация React-интерфейса | чтение, запись, bash |
| `test-writer` | Негативные и граничные тесты: права, IDOR, гонки, переходы статусов | чтение, запись, bash |
| `security-reviewer` | Независимое ревью каждого PR по чек-листу безопасности | только чтение |

Схема одного шага:

```
Человек: ставит задачу шага ──► plan mode: план
        │                               │
        │ утверждает план               ▼
        ▼                     backend-dev / frontend-dev: код + коммиты
   test-writer: тесты ◄───────────────┘
        │
        ▼
 security-reviewer: ревью diff ──► исправления
        │
        ▼
 PR ──► GitHub Actions (тесты, линтеры, сканеры) ──► человек смотрит diff и делает merge
```

Правила, которые удерживали качество:

- Общие правила проекта зафиксированы в `CLAUDE.md`; после каждой ошибки AI в файл добавлялось правило.
- Ни один шаг не начинался без утверждённого плана.
- Merge в `main` делал только человек после зелёного CI и просмотра diff.
- Секреты не передавались агентам: чтение `.env` запрещено настройками, деплой выполняют GitHub Actions.

## 3. Что делал человек, а что AI

| Этап | AI | Человек |
|---|---|---|
| Требования и архитектура | варианты решений, черновик документов | выбор стека, границы объёма |
| Код | основной объём | постановка шагов, просмотр каждого diff |
| Тесты | генерация | проверка, что тесты проверяют правильное |
| Безопасность | ревью, чек-лист | решения по компромиссам, настройка сервера и ключей |
| Деплой | написание workflow и compose | создание сервера, ключей, секретов |
| Демо-данные | генерация seed-скрипта | проверка правдоподобия |
